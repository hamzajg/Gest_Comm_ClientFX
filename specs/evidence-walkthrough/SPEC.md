# Spec: evidence-walkthrough

> Spec-driven development artifact. This file is the contract: implementation
> is done when every acceptance criterion maps to a scenario in
> `EXAMPLES.feature` and every scenario has a passing check.

## Problem

The client↔backend integration was proven only by ad-hoc smoke tests and a
one-off `docs/walkthrough/` dump of tracked PNGs. Tracked binaries bloat the
repo, go stale the moment the UI changes, and don't fit the spec-driven
delivery model used by the other managed repos. Evidence needs to be a
regenerable artifact: a spec dir that records what was proven, a tool that
re-produces the captures on demand, and binaries kept out of git.

## Users

- Maintainers and reviewers who need to verify the JavaFX client actually
  works against the live PyGestComm API without manual clicking.
- Future agents auditing delivery claims (the spec dir is the evidence
  record).

## Outcome hypothesis

- Expected user outcome: anyone can regenerate the full screen-by-screen
  evidence pack with two commands, and the repo carries zero screenshot
  binaries.
- Opportunity evidence: the harness already produced 16 captures during
  development; two latent dialog bugs were found and fixed by doing so.
- Signal: `git ls-files` shows no `*.png` under `docs/` or `specs/`; the
  screenshot tool exits 0 against a running backend.
- Follow-up owner/date: repo owner, at next UI change (regenerate then).

## Scope (in)

- `tools/Screenshots.java` — off-screen JavaFX renderer that loads each
  FXML, injects the live `ApiClient`, waits for async loads, and writes
  PNGs (2× scale) without showing windows.
- `specs/evidence-walkthrough/` — this spec dir: SPEC, EXAMPLES, BACKLOG,
  GATES, LOOP/WAVES/VALIDATION generated by the ship-loop oracle.
- `.gitignore` entry so regenerated captures stay untracked.
- `docs/walkthrough/WALKTHROUGH.md` content folded into this spec's
  validation record; the ad-hoc directory is removed from tracking and
  history.

## Scope (out)

- CI integration (captures require a live backend + desktop session).
- Video/GIF capture, native window chrome, OS-level automation.
- Backend (PyGestComm) spec artifacts — this spec covers the client repo.

## Acceptance criteria

| # | Criterion | Scenario(s) |
|---|-----------|-------------|
| 1 | Running the documented commands regenerates all screen captures as PNGs in an ignored directory | Regenerates every screen capture |
| 2 | No screenshot binaries are tracked anywhere in the repo | No image binaries are tracked |
| 3 | The spec records which screen each capture proves and how it maps to API calls | Walkthrough maps captures to screens |

## Decisions

- Evidence PNGs are **generated, not committed** — `docs/walkthrough/`
  is gitignored; history was rewritten to purge the previously tracked
  binaries (they remain reproducible via `tools/Screenshots.java`).
- The renderer stays a plain `javac`/`java` tool outside the Maven build
  so `mvn package` and CI are unaffected.
